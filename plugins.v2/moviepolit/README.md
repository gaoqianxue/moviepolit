# 流媒体上线监控（MoviePolit）

> MoviePilot V2 插件：监控指定地区流媒体平台**即将上线 / 近期上线**的电影、剧集，并监控**国内 B站 番剧 / 国创**排播与**豆瓣新上线**（腾讯视频 / 爱奇艺 / 优酷 / 芒果TV），调用 MoviePilot 已启用的通知渠道推送。

## 功能

- **两个方向**：`即将上线`（未来 N 天）与 `近期上线`（最近 N 天）。两者以**今天为界**互不重叠——“即将”从明天 0 点起算，“近期”包含今天，因此今天上线的条目归入“近期”分组，两个分组不会出现同一条目、也不会互相挤掉（若窗口在今天重叠，去重会把后查询的分组整批清空）。
- **两种媒体类型**：
  - 电影：按 TMDB **数字版（流媒体）上线日期** 统计，即真正“上线流媒体”的时间，而不是院线上映时间。因为 discover 接口返回的 `release_date` 是院线/首要发行日，插件会对候选影片逐条回查 `release_dates`，取该地区 **release type = 4（数字版）** 的真实日期来显示，并对不上窗口的条目直接剔除。
  - 剧集：按**首播日期**统计新剧 / 新季；另可选“近期更新”，捕捉最近有新剧集上线的剧集。
- **国内平台（B站）**：接入哔哩哔哩**番剧 / 国创**放送表，监控未来 8 天的排播，展示集数、更新时刻与追番数。这是独立于 TMDB 的数据源，走 B站公开接口，**无需鉴权、无需 Key**。
- **国内平台（豆瓣）**：接入豆瓣移动端「近期上线」集合（国产剧 / 热门剧集 / 热门综艺），补齐**腾讯视频 / 爱奇艺 / 优酷 / 芒果TV** 的上新信息——这些平台既没有公开 API，也不在 TMDB 收录范围内。展示集数、上线日期与实际可看平台，同样**无需鉴权、无需 Key**。
- **平台过滤**：只关注你指定的平台（iQIYI / WeTV / Netflix / Disney+ / Prime Video …），支持中文名、英文名或 TMDB 平台 ID。留空 = 该地区全部平台（推荐）。
- **平台识别**：自动从 TMDB 拉取该地区的平台清单（中英文名，缓存 7 天），识别失败的平台会在通知里给出提示和可用平台名。若按平台筛选在窗口内一条都没查到，会自动退回「该地区全部平台」重查并在通知里说明。
- **每条上线平台**：可选展示每部作品在该地区实际可看的具体平台（订阅 > 免费 > 广告 > 租借 > 购买）。
- **去重推送**：同一部作品只推送一次，不会今天“即将上线”、明天“已上线”重复通知。
- **通知内容**：带海报图 + 分组排版的文本，走 `self.post_message`，即 MoviePilot 里所有已启用的通知渠道（微信 / 企业微信 / Telegram / WxPusher …）。
- **详情页**：最近一次检测结果（海报墙 + 明细表）与推送历史。

## 数据来源与边界

数据来自**三个相互独立的来源**：

- **海外 / 港台流媒体**：**TheMovieDb**，直接复用 MoviePilot「设置 → 媒体识别 → TheMovieDb」中的 API Key、API 域名与图片域名、代理配置，**插件本身不需要填写任何密钥**。
- **国内平台（B站）**：**哔哩哔哩番剧 / 国创放送表**（`api.bilibili.com/pgc/web/timeline`），公开接口、无需鉴权与 Key，直连即可。
- **国内平台（豆瓣）**：**豆瓣移动端 rexxar 接口**（`m.douban.com/rexxar/api/v2/subject_collection/...`），公开接口、无需鉴权与 Key。

国内平台边界：

- **B站放送表最多覆盖未来 8 天**：接口硬限制 `before=0`、`after≤7`，无法回溯历史，也无法展望更远。窗口跟随「即将上线窗口」配置，但会被截断到 8 天。
- **豆瓣给出的是「已上线」而不是「即将上线」**：豆瓣集合（国产剧 / 热门剧集 / 热门综艺）本质是院线/首播语义，实测带平台信息的条目全部为已上线状态，`pre_playable_date`（可看日期）恒为空。因此豆瓣分组一律标注**「豆瓣新上线（最近 N 天）」**，只按 `pubdate` 归入「近期上线窗口」，**不承诺任何未来档期**——这是数据源的真实能力边界，不做美化。
- **豆瓣只接入剧集与综艺，不接入电影**：实测豆瓣电影集合（`movie_latest`）的平台覆盖率为 **0/20**，拿不到「在哪个平台可看」；且电影已由 TMDB 的数字版日期通道覆盖，重复接入只会产生噪音。
- **豆瓣条目会先按平台标记预筛**：列表项没有平台标记的条目不发起详情回查（实测国产剧 19/20、热门剧集 13/20、热门综艺 8/20 带标记），既省请求也避免推送“不知道在哪能看”的条目。
- **豆瓣同一部剧可能同时出现在多个集合**（`tv_domestic` 与 `tv_hot` 高度重叠），插件按豆瓣 ID 跨集合去重，只保留日期更新的一条。
- **延播条目自动剔除**：B站标记为延播（`delay=1`）的条目不会推送，避免给出错误时间。
- **同一剧集只保留最早一集**：8 天窗口内周更番可能跨多天出现多集，为避免刷屏只推送最早的一集；后续新集会在下一次检测时作为新条目推送。
- **三条通道互相独立**：任一侧接口失败不影响其他两侧。TMDB 正常而 B站/豆瓣失败时，插件仍会推送 TMDB 内容并在通知里以提示行说明；反过来亦然。只有**所有通道都失败**时才会发「检测失败」告警，避免误报。

TMDB 侧已知边界（不是 bug，均由 TMDB 数据现状决定）：

1. **TMDB 没有中国大陆的平台数据**：`/watch/providers` 在 `watch_region=CN` 下返回 0 条（MO 也是 0）。因此默认地区是 **TW**，请使用 **HK / TW / US / JP / KR / GB / SG** 这类有平台数据的地区；选 CN 时“监控平台”将无法识别，只能看到全部平台的结果。
2. **腾讯视频 / 优酷 / 芒果TV / 哔哩哔哩 完全不在 TMDB 平台库里**（全库 800+ 平台中只有 `iQIYI`、`WeTV` 等少数华语平台）。所以默认「监控平台」是**留空**的——预填这些名字只会让结果变空。（哔哩哔哩已由 B站接口覆盖，腾讯视频 / 爱奇艺 / 优酷 / 芒果TV 已由豆瓣通道覆盖。）
3. TMDB 的上线信息来自 JustWatch 等第三方，一部作品“即将上线”时平台数据往往还没关联上，**「即将上线」窗口内按平台筛选命中极少**（例如 US 未来 30 天不限平台 183 条、Netflix 仅 2 条）。想看得多就把「监控平台」留空，或主要依赖“剧集 · 近期更新”这一通道。
4. `with_release_type` 的日期窗口过滤**只认 `region`、不认 `watch_region`**，且即使传了 `region` 仍会有少量条目返回院线日期（实测 TW 12 条里有 3 条）。所以电影日期以逐条回查的数字版日期为准，回查不到或不在窗口内的影片不会出现在列表里。关闭「电影仅统计数字版上线」可放宽为全部发行日期。
5. 剧集的“近期更新”依据 TMDB 的剧集播出日期，仅对有完整分集数据的剧集有效。

## 安装

### 方式一：从插件市场安装（推荐，可自动更新）

1. 把本目录推送到你自己的 GitHub 仓库，保持如下结构：

   ```
   <你的仓库>/
   ├─ package.v2.json
   ├─ plugins.v2/
   │  └─ moviepolit/
   │     ├─ __init__.py
   │     └─ README.md
   └─ icons/
      └─ moviepolit.png（可选，插件图标）
   ```

2. MoviePilot →「设置 → 插件 → 插件市场」，把 `https://github.com/<你的用户名>/<仓库名>` 加入插件仓库地址。
3. 在市场中搜索「流媒体上线监控」并安装，或在「本地插件」里直接启用。

### 方式二：手动安装

把 `plugins.v2/moviepolit` 整个目录复制到 MoviePilot 的插件目录，目录名必须是**全小写**的 `moviepolit`：

```
<MoviePilot 根目录>/app/plugins/moviepolit/__init__.py
```

- Docker 部署通常是：`/app/app/plugins/moviepolit/__init__.py`
- 复制后在 MoviePilot →「设置 → 插件」中重载插件或重启容器；然后在本地插件里启用。

> 只有 `__init__.py` 是必需的，`README.md` 可一并放入。插件无第三方依赖，不需要 `requirements.txt`。

## 配置说明

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 打开后定时任务才会注册 |
| 立即运行一次 | 关 | 保存配置后立刻检测并推送一次，随后自动关闭该开关 |
| 消息类型 | 插件消息 | 对应 MoviePilot 的通知类型 |
| 检测时间 | `0 9 * * *` | 5 段 cron，默认每天 09:00 |
| 上线地区 | TW | CN/HK/TW/US/JP/KR/GB/SG；CN 无平台数据，建议 HK/TW/US |
| 监控平台 | 空 | 逗号分隔；留空 = 该地区全部平台（推荐，见「数据来源与边界」） |
| 监控电影 / 监控剧集 | 开 | 关闭则不做对应查询 |
| 含近期更新剧集 | 开 | 增加“最近有新集上线”的剧集 |
| 监控国内平台（B站） | 开 | 关闭则不请求 B站放送表 |
| B站番剧 | 开 | 监控番剧（types=1） |
| B站国创（国产动画） | 开 | 监控国创（types=4） |
| 国内平台新上线（豆瓣） | 开 | 关闭则不请求豆瓣接口；覆盖腾讯视频 / 爱奇艺 / 优酷 / 芒果TV |
| 豆瓣含综艺 | 开 | 关闭则不查询「热门综艺」集合 |
| 电影仅统计数字版上线 | 开 | 关闭后不再按 release type=4 过滤 |
| 即将上线窗口 | 30 天 | 未来多少天内的上线；国内平台受 B站接口限制最多 8 天 |
| 近期上线窗口 | 7 天 | 最近多少天内已上线；豆瓣新上线也按此窗口归集 |
| 单次推送最大条数 | 30 | 会影响 API 调用量与消息长度（0 按 100 处理） |
| 每种查询抓取页数 | 1 | 每页 20 条，建议 1~2 |
| 最低 TMDB 评分 | 0 | 0 = 不过滤 |
| 原始语言 | 空 | 如 `zh` 只看华语、`en` 只看英语 |
| 详情页历史保留天数 | 30 | 保留多少条推送历史 |
| 已推送过的不再重复推送 | 开 | 去重记录保留 180 天 |
| 显示每条作品的上线平台 | 开 | 每条作品额外请求一次 watch/providers |

## 常见问题

- **一条都没推送？** 先点「立即运行一次」看运行日志：日志里会写明查询通道、命中条数；若日志提示未识别的平台，按提示修改平台名或留空。
- **选 CN 后平台都识别不了？** 这是 TMDB 的数据现状（CN 无平台数据），改用 HK / TW / US 等地区；国内平台（B站 / 豆瓣）与地区设置无关，不受影响。
- **填了平台后推送变少甚至没有？** TMDB 在「即将上线」窗口内的平台数据很少，插件会自动退回全部平台重查；长期建议把「监控平台」留空。
- **想只看电影？** 关掉「监控剧集」（国内平台通道推送的都是剧集/综艺/番剧）。
- **想关掉国内平台？** 关掉「监控国内平台（B站）」与「国内平台新上线（豆瓣）」，插件将完全不请求这两个接口。
- **国内平台看不到 8 天以后的内容？** B站放送表接口的硬限制，最多未来 8 天，无法回溯或展望更远。
- **豆瓣为什么写的是「新上线」而不是「即将上线」？** 豆瓣只提供已上线的首播日期（`pubdate`），实测所有带平台信息的条目都是已上线状态，可看日期字段恒为空。写成「即将上线」会是假承诺，所以插件如实标注为「新上线」。
- **豆瓣有电影吗？** 没有，且是有意为之：实测豆瓣电影集合的平台覆盖率为 0，拿不到「在哪个平台可看」；电影已由 TMDB 数字版日期通道覆盖。
- **同一部剧怎么只出现一集？** 8 天窗口内周更番可能跨多天，为避免刷屏只推送最早的一集，后续新集会在下一次检测时推送。
- **腾讯视频 / 优酷 / 芒果TV 有监控吗？** 有，走豆瓣通道（「国内平台新上线（豆瓣）」），展示已上线的剧集与综艺；这些平台没有公开的未来排播接口，所以只覆盖「已上线」。
- **推送太频繁？** 打开「已推送过的不再重复推送」，并把 cron 调整为每天或每周一次。
- **通知里没有图片？** 部分渠道不支持图片，属正常现象。
- **电影日期和院线上映日不一样？** 正确行为：电影显示的是该地区的数字版（流媒体）上线日，与院线日期本就不同。
